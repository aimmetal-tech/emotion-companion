# 平台实例部署与训练操作手册

适用配置：咪咕大赛专属公有镜像 `vLLM:0.19.0-ubuntu22.04-p3.12-cuda12.8`，
单张 RTX 4090 24GB、64GB 内存、50GB 系统盘。

本手册采用“进入平台容器，在项目独立虚拟环境中训练”的路线，不要求在实例中再运行 Docker。
预装的 vLLM/PyTorch 环境保留；训练依赖安装到项目 `.venv/`。最终参赛镜像和评测入口仍按
官方赛事 PDF 及实际平台要求确认。

## 0. 执行顺序与计费提醒

1. 在服务器检查 GPU、Python、磁盘、持久目录和连接方式。
2. 放入代码和官方数据，再从本机上传已下载的基础模型及已编码的数据。
3. 校验文件，安装独立训练环境。
4. 检查 GPU 实际计算，运行微型模型与 7B 短测。
5. 保存基线，再启动正式训练。
6. 下载检查点、适配器、报告和预算账本，回本机合并导出模型。

**实例开机后的上传、安装、等待、空闲也可能消耗卡时。** 能在无卡状态完成的传输先完成。
预算工具只统计它启动的命令，不会自动关闭实例，平台账单和剩余卡时才是最终依据。
本手册按单卡运行；租用双卡时，即使只计算 GPU 0，也要核对双卡的实际计费。

命令块明确标记“本机”或“服务器”。本机命令按 Linux/WSL Bash 编写；服务器命令在平台终端
或 SSH 会话中执行。

## 1. 本机：填写 SSH 信息并连接

先把下面的示例值替换为平台提供的真实值。SSH 端口不一定是 22；用户名也不一定是 root。
项目路径以平台确认的持久目录为准，以下使用 `/mnt/storage/emotional-companion`，不要带空格。
若采用其他目录，除了修改本机的 `EC_REMOTE_DIR`，也要将下文服务器命令中的项目绝对路径
统一替换成相同位置。

```bash
export EC_SSH_HOST="填写服务器IP或域名"
export EC_SSH_USER="填写平台用户名"
export EC_SSH_PORT="22"
export EC_REMOTE_DIR="/mnt/storage/emotional-companion"

ssh -p "$EC_SSH_PORT" "$EC_SSH_USER@$EC_SSH_HOST"
```

若平台要求私钥认证，在 `ssh`、`scp` 命令中增加 `-i 私钥文件路径`。
使用 rsync 时，将同一参数放进 `-e "ssh ..."` 中。只有网页终端但没有 SSH/SFTP 入口时，
通过平台文件上传功能传输第 4 节列出的目录，不能直接使用下面的 SCP/rsync 命令。

重新打开本机终端后，要重新设置上述 `EC_*` 变量。


| 检查项 | 预期与处理 |
| --- | --- |
| GPU | RTX 4090，显存约 24GB；大量显存被占用时先定位进程，不要直接开始 7B 训练 |
| Python | 3.12；不符合时先核对所选镜像和 Python 路径 |

| GCC | bitsandbytes/Triton 启用 GPU 时编译辅助模块需要它 |
| tmux | 用于保持 SSH 断开后的训练会话；不能让任务跨关机或实例回收继续运行 |

```bash

```

非 root 账号需要平台管理员提供工具或按平台说明安装。不要在容器中尝试替换宿主机 NVIDIA 驱动。

## 3. 放入训练代码和官方原始数据

### 方式 A：服务器从 GitHub 克隆（推荐）

**服务器执行，首次部署时使用：**

```bash
git clone https://github.com/aimmetal-tech/emotion-companion.git \
  /mnt/storage/emotional-companion

cd /mnt/storage/emotional-companion
mkdir -p models artifacts runs
```

仓库包含 `src/`、`configs/`、`scripts/`、依赖锁文件、官方推理框架和原始训练/验证集。
**仓库不包含已下载的模型权重和 `artifacts/` 生成数据**，还需要第 4 节的上传。
目录已经有项目时，不要重复克隆或覆盖已有实验；先检查 `git status`，再按需要更新代码。

### 方式 B：本机上传源码（服务器无法访问 GitHub 时）

两种方式选择一种即可。本机和服务器都需要 rsync。

**本机执行，先进入本机项目根目录：**

```bash
cd /home/aimmetal/code/emotional-companion

ssh -p "$EC_SSH_PORT" "$EC_SSH_USER@$EC_SSH_HOST" \
  "mkdir -p '$EC_REMOTE_DIR' '$EC_REMOTE_DIR/models' '$EC_REMOTE_DIR/artifacts' '$EC_REMOTE_DIR/runs'"

rsync -avP --exclude='__pycache__/' --exclude='*.pyc' \
  -e "ssh -p $EC_SSH_PORT" \
  pyproject.toml uv.lock requirements.txt .python-version .gitignore .dockerignore \
  AGENTS.md README.md Dockerfile.training \
  src configs scripts tests docs official_dl \
  "$EC_SSH_USER@$EC_SSH_HOST:$EC_REMOTE_DIR/"
```

这是指定文件列表的上传，不会把本机 `.venv`、缓存、Git 元数据、模型和实验结果混进源码。
其中 `official_dl/` 包含原始数据集和官方推理程序。

## 4. 本机：上传已准备好的数据和权重

| 本机目录 | 服务器相对位置 | 用途 |
| --- | --- | --- |
| `models/qwen2.5-7b-instruct/` | 同名位置 | 基础权重、配置、tokenizer 和 `SHA256SUMS`，约 15GB |
| `artifacts/data/` | 同名位置 | 清洗数据、开发集、评估子集和审计记录，约 117MiB |
| `artifacts/tokens-4096/` | 同名位置 | 默认编码数据，约 285MiB |
| `artifacts/tokens-2048/` | 同名位置 | 备用编码数据，约 245MiB，建议同时上传 |

这些数据已在本机处理和验证，服务器不用再次执行 `download`、`prepare` 或 `tokenize`。

### 方式 A：rsync 上传（推荐，方便中断后重跑）

**本机执行：**

```bash
cd /home/aimmetal/code/emotional-companion

rsync -avP -e "ssh -p $EC_SSH_PORT" \
  models/qwen2.5-7b-instruct \
  "$EC_SSH_USER@$EC_SSH_HOST:$EC_REMOTE_DIR/models/"

rsync -avP -e "ssh -p $EC_SSH_PORT" \
  artifacts/data artifacts/tokens-4096 artifacts/tokens-2048 \
  "$EC_SSH_USER@$EC_SSH_HOST:$EC_REMOTE_DIR/artifacts/"

scp -P "$EC_SSH_PORT" \
  artifacts/server-ready-manifest.json \
  artifacts/model-verification.json \
  artifacts/tokenization-verification.json \
  "$EC_SSH_USER@$EC_SSH_HOST:$EC_REMOTE_DIR/artifacts/"
```

中断后重跑同一条 rsync 命令。`-P` 保留部分文件并显示进度；此处目录名后面没有 `/`，
因此复制的是目录本身，不要随意改变结尾斜线导致少一层或多一层目录。

### 方式 B：SCP 上传（没有 rsync 时）

**本机执行：**

```bash
scp -P "$EC_SSH_PORT" -r \
  models/qwen2.5-7b-instruct \
  "$EC_SSH_USER@$EC_SSH_HOST:$EC_REMOTE_DIR/models/"

scp -P "$EC_SSH_PORT" -r \
  artifacts/data artifacts/tokens-4096 artifacts/tokens-2048 \
  "$EC_SSH_USER@$EC_SSH_HOST:$EC_REMOTE_DIR/artifacts/"
```

SCP 指定端口用大写 `-P`，SSH 则用小写 `-p`。SCP 中断后重新复制可能需要重传大文件，
优先使用 rsync 或平台提供的续传工具。若平台只提供文件管理器，按本节相对位置上传即可。

**本路线不用上传：** 本机 `.venv/`、`.cache/`、Docker 镜像 tar、旧的微型测试 `runs/`。
新训练的 `runs/` 从服务器开始产生。已有正式训练预算账本时，需保留同一份 `runs/budget.json`，
不能靠新建账本重置已消耗的卡时。

## 6. 服务器：安装项目独立训练环境

可选用下面的 pip 方式或后面的 uv 方式，两种方式选择一种即可。

### 方式 A：使用 requirements.txt 和 pip

根目录的 `requirements.txt` 从 `uv.lock` 的 `training` 依赖组导出，包含固定版本的
训练依赖及其间接依赖，不包含 vLLM、开发工具和项目本身。使用 Python 3.12 创建独立环境：

```bash
cd /mnt/storage/emotional-companion

python3.12 -m venv .venv
.venv/bin/python -m pip install --no-cache-dir \
  -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
.venv/bin/python -m pip install --no-cache-dir --no-deps -e . \
  -i https://pypi.tuna.tsinghua.edu.cn/simple
.venv/bin/python -m pip check
.venv/bin/python -m emotional_companion --help
```

第二条安装命令用于注册 `src/` 下的项目包，不能只装依赖就直接运行训练入口。
AutoDL 若采用 `~/autodl-tmp/emotion-companion-main`，将本手册的项目路径替换为该目录。

### 方式 B：使用 uv 和锁文件

先检查 `uv --version`。没有 uv 时安装官方工具：

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"
uv --version
```

在项目根目录安装依赖，固定使用平台已提供的 Python 3.12，不下载另一套 Python：

```bash
cd /mnt/storage/emotional-companion

UV_PROJECT_ENVIRONMENT="$PWD/.venv" \
UV_PYTHON_DOWNLOADS=never \
UV_DEFAULT_INDEX=https://pypi.tuna.tsinghua.edu.cn/simple \
uv sync --locked --extra training --no-dev --no-cache --python 3.12
```

`--locked` 使用仓库锁定的版本；`--no-cache` 减少 50GB 系统盘上的安装缓存。
依赖首次安装仍需联网和若干 GB 空间。不要向系统 Python 直接安装训练依赖，也不要复制本机
`.venv` 到平台。后续都调用项目 `.venv/bin/python`，预装 vLLM 环境保持独立。

安装报网络错误时先核对平台网络；锁文件错误时确认 `pyproject.toml` 与 `uv.lock` 来自同一版本，
不要为了跳过错误直接升级依赖。Python 3.12 未找到时先检查镜像或现有解释器路径。

## 7. 服务器：检查训练依赖和 GPU 实际计算

```bash
cd /mnt/storage/emotional-companion
export CUDA_VISIBLE_DEVICES=0
export PYTHONHASHSEED=42
export TOKENIZERS_PARALLELISM=false

.venv/bin/python - <<'PY'
import torch
import transformers
import peft
import bitsandbytes

print("PyTorch:", torch.__version__)
print("CUDA runtime:", torch.version.cuda)
print("Transformers:", transformers.__version__)
print("PEFT:", peft.__version__)
print("bitsandbytes:", bitsandbytes.__version__)
assert torch.cuda.is_available(), "CUDA 不可用"
assert torch.cuda.device_count() == 1, "训练应只看到一张 GPU"
print("GPU:", torch.cuda.get_device_name(0))
print("显存 GiB:", torch.cuda.get_device_properties(0).total_memory / 1024**3)
print("BF16:", torch.cuda.is_bf16_supported())
assert torch.cuda.is_bf16_supported(), "GPU 不支持 BF16"
x = torch.randn(256, 256, device="cuda", dtype=torch.bfloat16)
y = x @ x
torch.cuda.synchronize()
assert torch.isfinite(y).all().item()
print("GPU 计算检查通过")
PY
```

本机已验证的依赖包括 PyTorch 2.6.0、Transformers 4.57.6、PEFT 0.18.1、bitsandbytes 0.49.2。
CUDA runtime 显示 12.4 与平台镜像名称中的 12.8 不同，不等于运行失败；需要以上实际计算检查
通过。若 CUDA、BF16、量化模块导入或计算失败，先处理具体错误，不启动长训练。

上传数据的校验也会在训练入口自动执行：编码文件哈希、模型配置哈希、序列长度与提示哈希种子
必须匹配。主训练使用 4096 数据；切换 2048 时须同时指定 `--max-length 2048`。

## 8. 服务器：记录初始化用量，进入持久会话

安装、上传和等待不在预算执行器的计时范围内，要先根据实际实例开机时间记账。
下面只是示例：**仅当单卡初始化确实用了 30 分钟时记入 0.5 卡时，不要盲目照抄数字。**

```bash
.venv/bin/python -m emotional_companion budget record \
  --stage recovery --gpu-hours 0.5 --note "platform setup: 30 minutes"

.venv/bin/python -m emotional_companion budget status
```

初始化记账属于 2 卡时的恢复余量；如准备工作已超出余量，先重新核对总预算和训练安排，
不要通过删除账本或忽略平台用量继续运行。

```bash
tmux new -s ec-train
```

进入 tmux 后再次设置项目位置和环境，后续 GPU 命令在这个会话里执行：

```bash
cd /mnt/storage/emotional-companion
export CUDA_VISIBLE_DEVICES=0
export PYTHONHASHSEED=42
export TOKENIZERS_PARALLELISM=false
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1
```

按 `Ctrl+B` 后按 `D` 可以离开会话；重新登录后执行 `tmux attach -t ec-train` 返回。
tmux 只应对终端断连，不能保护被关机、删除或回收的实例。

## 9. 服务器：先短测，再正式训练

每条命令成功后再执行下一条。首次使用下面的输出目录；失败重跑或新实验请指定新的目录，
不要覆盖既有实验。

### 9.1 微型模型端到端检查

```bash
.venv/bin/python -m emotional_companion budget run \
  --stage recovery --gpus 1 --hours 0.1 -- \
  .venv/bin/python -m emotional_companion smoke \
  --device cuda --output runs/platform-smoke
```

检查 `runs/platform-smoke/smoke_report.json` 中 `passed` 是否为 `true`。
它验证流程，不代表正式 7B 模型的显存需求或效果。

### 9.2 实际 7B 模型短测

```bash
.venv/bin/python -m emotional_companion budget run \
  --stage baseline_smoke --gpus 1 --hours 0.5 -- \
  .venv/bin/python -m emotional_companion train \
  --max-steps 50 --output runs/smoke-50
```

50 步完成后查看 `runs/smoke-50/throughput.json` 和 `training_report.json`，确认显存和速度。
未到 50 步即达到时限时，`throughput.json` 可能未生成；先看实际训练状态和已有检查点。

显存不足时使用已上传的备用数据，在新目录重试，且预算时长不能超过阶段剩余额度：

```bash
# 这里 0.5 小时是示例上限；若本阶段已用过额度，改为实际剩余时长。
.venv/bin/python -m emotional_companion budget run \
  --stage baseline_smoke --gpus 1 --hours 0.5 -- \
  .venv/bin/python -m emotional_companion train \
  --data artifacts/tokens-2048 --max-length 2048 \
  --max-steps 50 --output runs/smoke-50-2048
```

不要将 2048 数据用于恢复 4096 的旧训练。

### 9.3 原模型评估基线

```bash
.venv/bin/python -m emotional_companion budget run \
  --stage baseline_smoke --gpus 1 --hours 0.5 -- \
  .venv/bin/python -m emotional_companion evaluate \
  --output runs/baseline-quick
```

短测和基线共享 1 卡时额度，多次重试后先查看 `budget status`；必要时缩短下一次命令的预留时长。

### 9.4 主训练

4096 短测通过后：

```bash
.venv/bin/python -m emotional_companion budget run \
  --stage train --gpus 1 --hours 9 -- \
  .venv/bin/python -m emotional_companion train
```

若短测最终选择 2048，将最后一行改为：

```bash
.venv/bin/python -m emotional_companion train \
  --data artifacts/tokens-2048 --max-length 2048 --output runs/train-2048
```

仍应通过前面的预算执行器启动，不要跳过限时。训练最多两轮，是否能完成由速度和 9 卡时
限制决定。默认产物在 `runs/train/`，2048 方案则在 `runs/train-2048/`。

中断恢复时使用相同目录、数据和配置，向训练命令增加 `--resume latest`；预算中的 `--hours`
改成该阶段剩余时长，不再次申请完整 9 小时。检查点包含优化器和训练进度，`adapter/`
不能代替完整恢复检查点。

### 9.5 训练后快速评估

```bash
.venv/bin/python -m emotional_companion budget run \
  --stage eval --gpus 1 --hours 1 -- \
  .venv/bin/python -m emotional_companion evaluate \
  --adapter runs/train/adapter --output runs/candidate-quick
```

2048 方案将适配器路径改为 `runs/train-2048/adapter`。比较基线和微调结果，随后完成 README
中的人工盲评；流程跑通不等于模型效果达标。

## 10. 本机：下载训练结果，服务器停止 GPU 资源

训练完成或中断后，先下载整个 `runs/`，其中包含检查点、适配器、报告、评估结果和预算账本。
本机已经有基础模型及相同编码数据，不必从服务器重复下载这些文件。

**本机执行，使用本节专用的新备份目录，避免覆盖旧实验：**

```bash
mkdir -p artifacts/platform-backup

rsync -avP -e "ssh -p $EC_SSH_PORT" \
  "$EC_SSH_USER@$EC_SSH_HOST:$EC_REMOTE_DIR/runs/" \
  artifacts/platform-backup/runs/
```

没有 rsync 时：

```bash
scp -P "$EC_SSH_PORT" -r \
  "$EC_SSH_USER@$EC_SSH_HOST:$EC_REMOTE_DIR/runs" \
  artifacts/platform-backup/
```

首次使用该备份目录；后续不同实例/实验使用不同目录名。确认文件下载成功后，在平台停止 GPU
资源；长期保存问题以平台持久存储规则为准。若可使用无卡状态访问文件，优先在无卡状态下载。

50GB 实例上不合并保存完整模型和提交副本。使用下载回来的适配器，在本机 CPU 上导出：

```bash
cd /home/aimmetal/code/emotional-companion

CUDA_VISIBLE_DEVICES=-1 HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
  .venv/bin/python -m emotional_companion export \
  --adapter artifacts/platform-backup/runs/train/adapter \
  --output models/companion-7b
```

2048 训练则将适配器路径中的 `train` 改成 `train-2048`。导出需要本机内存和磁盘空间；
当前本机已验证完整 7B 模型的 CPU 离线加载和短推理。若导出目录已有内容，使用新目录。
最终提交包及平台官方入口验证另按 README 和赛事要求执行，不在首次部署时消耗正式测评机会。

## 11. 常见问题与对应检查

| 现象 | 检查与处理 |
| --- | --- |
| 模型文件找不到 | 核对项目工作目录，避免 `models/models/...` 或多套一层模型目录 |
| 编码数据找不到 | 权重已上传不等于数据已上传，检查 `artifacts/tokens-4096/` |
| 模型分片校验失败 | 只重传失败分片，校验通过前不训练 |
| tokenization/config/hash 不匹配 | 传输完整编码目录，使用对应长度和未改动的基础模型配置 |
| 提示哈希种子不匹配 | 设 `PYTHONHASHSEED=42`；不要重新编码已验证的数据 |
| CUDA 不可用 | 检查平台 GPU 分配、驱动和项目 `.venv`；不在容器里安装驱动来掩盖问题 |
| Triton 找不到编译器 | 检查 `gcc` 和 C 头文件；本机镜像已遇到并解决过此问题 |
| 显存不足 | 看 GPU 占用，确认只暴露一张卡；按第 9 节切换 2048 数据 |
| 系统盘空间不足 | 不上传镜像 tar/本机虚拟环境，使用无缓存依赖安装；完整导出放在本机 |
| 新训练目录非空 | 新实验使用新目录；恢复现有实验用 `--resume`，不要直接删除检查点 |
| 预算额度拒绝启动 | 查看 `budget status` 和平台实际余额，按阶段剩余时间调整预留 |
| 终端断开 | 重新 SSH 后 `tmux attach -t ec-train`；实例关机/回收后需从检查点恢复 |
